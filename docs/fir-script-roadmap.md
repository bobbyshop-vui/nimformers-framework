# FIR script runtime engineering roadmap

## Summary

The starting point is a metadata tracer, typed SSA graph, generated F32 micro-kernels, and a scalar-token `runtime graph` executor. The repository contains numerical fixtures for GPT-2, Llama with MHA/GQA and RoPE, and a Mamba-1-style block. Those specific graphs provide the regression baseline. Sources: [docs/fir-script.md:3–9, 183–190, 222–249](/Volumes/Data/Laptrinh/App/nimformers-framework/docs/fir-script.md:3), [test_fir_numerics.py:225–297](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/python/tests/test_fir_numerics.py:225).

The recommended order is: establish VM/backend conformance; load common checkpoint dtypes; introduce script-only typed storage, integer metadata and resource descriptors; support both linear orientations and quantization; add bounded dynamic shapes and chunked prefill; then build cooperative reductions, memory planning, attention variants, recurrent scans, MoE and vision operators. General inference also needs entry points with arbitrary tensor inputs/outputs, not just a larger operator list.

`layout script` is the compatibility boundary. Today it changes arena placement of non-matrix F32 weights only; it does not enable a different instruction set, scheduler, dtype system or input ABI. Preserve default/explicit `classic` behavior and existing script files. Sources: [fir_parse.bybylang:56–60, 126–129](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/src/formers/ir/fir_parse.bybylang:56), [fir_graph_kernels.bybylang:8–23](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/src/formers/ir/fir_graph_kernels.bybylang:8), [fir_graph.bybylang:67–92, 239–284](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/src/formers/ir/fir_graph.bybylang:67).

Sections 2–4 are proposals. Every new mnemonic, builtin and syntax form there is **proposed**, not an existing interface. **Hypothesis** labels identify estimates, projected performance, unexecuted failure scenarios and illustrative deployment assumptions. Current behavior below is established by the cited working-tree source or documentation; line numbers refer to that snapshot.

## 1. Exact current runner and VM limits

### 1.1 Pipeline and the existing layout gate

The tracer calls the Python module with proxies, records concrete positive shapes, requires one returned proxy and optionally applies graph passes. `Weight` and `Value` contain dtype metadata, and nodes record persistent-state writes. Symbolic `Dim` values specialize during tracing. Sources: [tracer.py:35–76, 95–126](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/python/formers/fir/tracer.py:35), [graph.py:7–47](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/python/formers/fir/graph.py:7).

Emission explicitly requires scalar token and position roles, a vocabulary-sized output and a positive fixed context. It rejects nested `ssm_cfg`, emits `runtime graph` plus `layout script`, and guards positive integer config specializations with `require sym`. The optional FX adapter constructs parameter descriptors from names/shapes, imports torch on demand and rejects unsupported targets; its parameter construction does not preserve the source torch dtype. Sources: [emitter.py:194–209, 390–423](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/python/formers/fir/emitter.py:194), [torch_adapter.py:9–29, 55–89](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/python/formers/fir/torch_adapter.py:9).

### 1.3 Registers, addresses, threadgroups and memory ownership

Each lane has 32 F32 registers and 32 uint32 registers. Production CPU and JIT initialize R0 to the global thread ID and zero the remaining registers; Python codegen reserves R0 and allocates R1–R31/U0–U31. Generated kernels currently use `tg=1 tgbytes=16`, with one dimension distributed across lanes and other dimensions in serial loops. Sources: [cpu_vm.c:49–58, 148–154](/Volumes/Data/Laptrinh/App/nimformers-framework/vendor/bybylang/backends/cpu/cpu_vm.c:49), [jit_vm.nim:462–468, 494–504](/Volumes/Data/Laptrinh/App/nimformers-framework/vendor/bybylang/micro_kernel/jit_vm.nim:462), [codegen.py:13–17, 150–177, 259–319, 532–537](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/python/formers/fir/codegen.py:13).

Kernel expressions resolve config symbols, `eps`, `pi`, port element counts, `sqrt(...)` and absolute arena offsets such as `@in0`, `@out0` and `@buffer_name` when programs are assembled. `@inN`/`@outN` shorthand recognizes one decimal digit. A rank-2 resident matrix has no arena binding; Python therefore emits a separate F32 `SOURCE.fir_flat` checkpoint tensor for micro-kernel reads of a matrix. Sources: [fir_kernel.bybylang:8–11, 31–40, 99–116, 204–220](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/src/formers/ir/fir_kernel.bybylang:8), [emitter.py:457–490](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/python/formers/fir/emitter.py:457).

Arena offsets count F32 elements. An R-based variable index cannot represent every integer above 2^24; U registers provide uint32 addressing. This is an arithmetic range, not an allocation guarantee: a theoretical 2^32 F32 slots spans 16 GiB, while the production CPU interface passes lengths and thread counts through C `int`. Sources: [vendor session_vm.nim:47–70](/Volumes/Data/Laptrinh/App/nimformers-framework/vendor/bybylang/micro_kernel/session_vm.nim:47), [cpu_backend.nim:361–370](/Volumes/Data/Laptrinh/App/nimformers-framework/vendor/bybylang/backends/cpu/cpu_backend.nim:361). The byte-to-GiB conversion is arithmetic derived from those types.

The memory protection models differ. Python checks each load against input/output port intervals and each store against output intervals. The production CPU VM checks global arena bounds, not node-port boundaries. JIT loads/stores are direct pointer indexing. The FIR assembler even permits a named arena address outside a node's ports. Sources: [vm.py:393–432](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/python/formers/fir/vm.py:393), [cpu_vm.c:118–124, 377–398](/Volumes/Data/Laptrinh/App/nimformers-framework/vendor/bybylang/backends/cpu/cpu_vm.c:118), [jit_vm.nim:278–289](/Volumes/Data/Laptrinh/App/nimformers-framework/vendor/bybylang/micro_kernel/jit_vm.nim:278), [fir_kernel.bybylang:31–40](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/src/formers/ir/fir_kernel.bybylang:31).

There is another address-conformance boundary: Python wraps the effective U+immediate address to uint32; JIT emits uint arithmetic; CPU promotes the U operand and immediate to int64 before adding. Codegen emits negative strides using uint32 two's complement. **Hypothesis:** some negative-stride exports that pass Python can fail production CPU bounds checks when a valid effective address requires that final addition to wrap. Add a targeted conformance fixture before claiming cross-backend parity for this case. Sources: [vm.py:424–430](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/python/formers/fir/vm.py:424), [jit_vm.nim:278–283](/Volumes/Data/Laptrinh/App/nimformers-framework/vendor/bybylang/micro_kernel/jit_vm.nim:278), [cpu_vm.c:377–389](/Volumes/Data/Laptrinh/App/nimformers-framework/vendor/bybylang/backends/cpu/cpu_vm.c:377), [codegen.py:162–166](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/python/formers/fir/codegen.py:162).

Threadgroup storage is separate from the arena and shared only within a group. FIR validates positive dispatch sizes, exact divisibility of threads by group size and nonnegative shared bytes; the graph executor supplies at least four shared floats. There is no device-wide barrier in the FIR text set. Cooperative algorithms must use distinct dispatches between groups. Sources: [fir_exec.bybylang:123–134](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/src/formers/ir/fir_exec.bybylang:123), [fir_graph.bybylang:185–196](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/src/formers/ir/fir_graph.bybylang:185), [vendor session_vm.nim:23–26](/Volumes/Data/Laptrinh/App/nimformers-framework/vendor/bybylang/micro_kernel/session_vm.nim:23).

### 1.4 Dispatch, sessions and residency

Preparation requires `runtime graph`, symbols `layers`/`positions`/`vocab` and token/position/logits roles, validates the graph, and assembles a program for each micro node and layer address. Model-defined kernels override registry micro builders. Metal uses prepared JIT pipelines, Vulkan prepares GLSL jobs, and CPU invokes production `cpu_backend.vmRun`; the separate `vm_interp.nim` is a test interpreter. The JIT cache is configured with hot threshold 1 and maximum 1024 entries. ## 2. Capability designs and concrete changes

### Shared script extension contract

Adopt the following design rules for every capability (a)–(m):

1. Add a script extension revision, proposed `script_abi 1`, and capability declarations such as `require feature typed_storage_v1`. Resolve layout in a header pass before validating gated declarations, preserving existing files that put `layout` late. Accept new fields/mnemonics/builtins only with `layout script`; reject them for default/explicit classic. Preserve old script files without the revision on their existing F32 path. Keep `fir 1` and the legacy VM opcode numbers stable; allocate new opcode values rather than reinterpret existing ones. The existing late-layout regression fixture is at [test_fir.bybylang:329–335](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/tests/test_fir.bybylang:329).
2. Introduce a script resource descriptor: storage identity/handle, dtype, logical shape/strides, capacity, byte offset/alignment, readable/writable ports, alias set and lifetime. Keep existing `@buffer` F32-element addresses unchanged. Proposed typed instructions use a port operand, e.g. `tloadf16 rD uIndex in0`, where `uIndex` is relative to that resource in logical elements. This prevents mixing bytes, F32 slots and packed quantization units. Encode the port as a descriptor slot, with checked byte arithmetic in the loader/planner and typed access in each backend. Bind a bounded set of arena shards/weight resources per dispatch; do not require unrestricted bindless support.
3. Add proposed `loadparamu uD SLOT` and `loadparamf rD SLOT` to read typed runtime metadata, using a dedicated descriptor/parameter binding. These are not numeric loads through R. Declare capacities separately from active lengths, check multiplication/offset overflow before allocating/encoding, and report missing backend capabilities before uploading weights.
4. Add a true resident builtin encoder table to the graph runner. New `builtin script.*` entries receive device resource descriptors and encode into the open session; they must not use the host-sequence `FirExtProc` ABI. Preserve old `fir.*` external encoding and the classic Mamba provider. Extend parser/type records, validation, assembly, Metal/GLSL JIT, CPU VM and Python VM together for each new instruction.
5. Proposed node attributes follow a `; key=value` delimiter after outputs. Parse attributes separately from buffer names and reject unknown keys. Entry/region/typed syntax examples below are extension designs, not valid current FIR. Add an explicit backend feature manifest and deterministic errors instead of silently changing precision or evaluating unsupported operations on the host.

### (k) Static unrolling versus runtime loops/conditionals

**Minimal design.** Continue static unrolling for config-known loops/branches. Add explicit bounded control operators for runtime data; do not attempt to capture arbitrary Python branching by executing it. Separate within-kernel control, host-known graph iteration counts, and device-dependent multi-node regions.

**Runner/VM/FIR.** Add script region records rather than storing control only in node strings. Proposed `loop count=T max=128 carry=...`/`endloop`, `cond predicate`/`else`/`endcond`, with typed scalar predicates, shape-compatible yields and declared state effects. Host-known counts can schedule repeated regions without readback. Within one micro-kernel use existing immutable-count loops or proposed `uforbegin`/`uifbegin`.

For device predicates spanning dispatches, first support pure branch evaluation plus select, and bounded iterations with an active mask. Stateful branches require predicate-aware builtin encoders/kernels that suppress writes and RNG/state advancement in inactive regions. External GEMM may perform unused pure work, but its effects must be confined to temporary outputs. Reject unsupported stateful regions at validation. A truly device-dependent unbounded loop is outside this first capability; a later explicit host-feedback mode would need synchronization and a separately visible execution contract. Validate uniformity of all threadgroup barriers under control flow, and cap total region work as well as per-dispatch work.

**Python tracer/lowering.** Add explicit `cond`/bounded-loop graph APIs or convert supported exported control regions, with typed carried values and effect/alias joins. Perform shape/dtype checks on both branches without reading tensor payloads. Emit static regions when counts/predicates are provably constant; diagnose graph growth and budget overruns.

**Tests / acceptance.** Zero/max loops, both predicate outcomes, changed carried shapes rejected, state written on one branch only, inactive RNG unchanged, nested regions, no barrier in divergent lane control, and bounded nontermination errors. Include an immutable-count conformance test and a rejection fixture for mutating legacy loop counts. Do not change classic CPU/JIT loop behavior as a side effect of script control support.

**Risk.** Predicating arithmetic without predicating state/RNG writes is incorrect. **Hypothesis:** bounded active masks cover initial adaptive inference needs at acceptable wasted-work cost; quantify before adding host feedback or indirect graph control.

### (l) Multiple repeat stacks and heterogeneous layers

**Minimal design.** Model repeats as named regions with their own count/index and state/weight templates. Permit explicit heterogeneous layer schedules; compress only subregions proven structurally identical. Support multiple activation carries when the region contract declares them.

**Runner/VM/FIR.** Proposed `repeat encoder_layers as e`/`endrepeat` and `repeat decoder_layers as d`, templates `{e}`/`{d}`, and `per_repeat=e` storage attributes. Replace the boolean `perLayer` scheduling model with a region tree and lexical index environment for script ABI files. Preserve scope boundaries even when repeats are adjacent; allocate per-region capacities and compile/cache programs by resolved resources/layout. Represent alternating attention/SSM/MoE layers by explicit ordered nodes or a validated static schedule table with per-layer weight/state descriptors. Keep classic `{i}`/`repeat layers` allocation/order exactly as before.

**Python tracer/lowering.** Extend `extract_repeats` to return multiple independent regions and tuple carries, with immutable external captures, escaped-value checks and nonhomogeneous fallback. Retain layer-local checkpoint identities outside folded regions. Choose explicit unrolling when compression would require unsafe aliases; report graph size instead of raising merely because two legal homogeneous stacks exist. The current candidate checks and error are at [repeat.py:47–93](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/python/formers/fir/repeat.py:47).

**Tests / acceptance.** Adjacent named repeats with different counts, encoder/decoder cross-attention, two carries, a residual used after a stack, a later layer's weight used outside the stack, tied cross-stack weights and alternating SSM/attention state shapes. Compare folded and fully unrolled schedules for outputs, resource addresses and states. Use parse/plan-only large-layer fixtures to check program count/cache growth without running a large model.

**Risk.** Incorrect lexical template substitution or aliasing can silently apply one stack's weights/state to another. Address-specialized bytecode can grow with layers; descriptor-based reuse must be tested independently of textual body deduplication.

### (m) Large-model memory planning, streaming and the 8 GB target

**Minimal design.** Build a byte-accounted plan before allocation: resident weights/metadata, persistent cache/state, live activations, temporary workspace, readback, upload staging and backend reserve. Use liveness-based arena reuse with alias/effect constraints and stable persistent-state addresses. Prefer all-resident packed weights when they fit; otherwise select explicit layer/expert streaming with bounded staging and fences.

**Runner/VM/FIR.** Proposed `memory budget=... reserve=...`, weight `residency=resident|stream`, and buffer `lifetime=persistent|entry|temporary` attrs. Make resource/arena planning a script-only path in `firGraphBindings`/allocation, using checked 64-bit host byte arithmetic and backend-reported buffer/allocation limits. Separate arena shards and bind resource-relative U indices within each shard; do not turn uint32 indexing into an implicit 16 GiB allocation promise. Bind matrices directly through descriptors/views to avoid duplicate `.fir_flat` payloads and, where backend APIs permit, the two linear activation copies.

Extend loading to a validated sharded checkpoint index and bounded conversion tiles; prepack large matrices offline or pack incrementally, so source F32 plus full transpose are not required concurrently. Runtime streaming uses at most a declared number of weight slots, uploads the next layer/expert, waits on the correct completion fence before slot reuse, and keeps activations/state resident. Pin required embeddings/norms or plan them explicitly. Add allocation failure cleanup and state invalidation; expose the full plan and actual peak bytes in diagnostics. Mapped/shared host resources are an optimization to investigate: backend wrapping/mapped Q4 APIs exist, but the reviewed graph loader uses ordinary per-tensor upload, not those APIs. Sources: [gpubackend.nim:2544–2562, 2584](/Volumes/Data/Laptrinh/App/nimformers-framework/vendor/bybylang/gpubackend.nim:2544), [fir_graph.bybylang:67–92, 163–180](/Volumes/Data/Laptrinh/App/nimformers-framework/other/formers.n/src/formers/ir/fir_graph.bybylang:67).

**Memory arithmetic.** For a matrix `[N,K]`, current grouped asymmetric Q4 requires `N*ceil(K/2)` packed bytes plus `8*N*ceil(K/32)` metadata bytes, excluding allocation overhead; both scales and zero points are F32. This follows directly from [quant.nim:155–169](/Volumes/Data/Laptrinh/App/nimformers-framework/quant.nim:155). For aligned K this is **0.75 byte/weight, or 6 bits/weight**, rather than 0.5 byte total.

| Illustrative 7,000,000,000-parameter weight plan | Derived bytes / GiB | Meaning |
| --- | --- | --- |
| All F32 | 28,000,000,000 / 26.08 GiB | Arithmetic storage baseline. |
| All F16/BF16 | 14,000,000,000 / 13.04 GiB | Still exceeds either an 8 GB or 8 GiB total budget. |
| All current Q4, aligned groups of 32 | 3.5 GB packed + 1.75 GB scales/zeros = 5.25 GB / 4.89 GiB | Optimistic weight-only calculation; real matrices/vectors/tied tables and padding require an exact manifest sum. |
| Proposed symmetric Q8 with one F32 scale per 32 weights | 7.875 GB / 7.33 GiB | Hypothesis: illustrative proposed format, excluding nonquantized tensors and overhead. |

**Hypothesis: illustrative deployment budget.** With an 8 GiB total-memory target, the optimistic 4.89 GiB Q4 plan leaves 3.11 GiB for everything else. For assumed 32 layers, B=1, 2048 slots, 8 KV heads, D=128 and F16 K/V, cache bytes are `2*32*1*2048*8*128*2 = 256 MiB`; 32 KV heads require 1 GiB, and F32 doubles either cache. Reserving an illustrative 2 GiB for the OS/application and 0.75 GiB for activations, pipelines, staging and allocator overhead leaves about 0.11 GiB with the GQA example and exceeds budget with the MHA example. These are assumptions for planning, not a fit/performance result. A decimal 8,000,000,000-byte budget is about 7.45 GiB and is tighter still.

The acceptance target should therefore be a **named 7B manifest + chosen quantization + batch/context + measured free-memory budget**, not “any 7B fits 8 GB.” Prioritize oi quantization, compact metadata where quality allows, half caches, limited prefill chunks and elimination of duplicate matrices. If the exact plan does not fit, reduce a declared capacity or stream selected weights; never silently wrap context or overcommit. **Hypothesis:** streaming latency will be dominated by effective transfer/storage bandwidth; a lower-bound estimate is streamed bytes per token divided by measured bandwidth, and overlap must be measured on each machine.

**Python tracer/lowering.** Emit liveness/alias/state information, separate parameter source identity from storage views, expose chosen capacities and workspace requirements, and produce a deterministic memory-plan report from metadata. Make fusion cost-aware so saved dispatches do not create an oversized live temporary. Include per-entry and per-repeat resource use.

**Tests / acceptance.** CPU-only symbolic planning for 7B-scale shapes without allocating payloads; interval/alias checking, overflow rejection, injected allocator failures and exact accounting for padding/scales/zeros. Tiny synthetic streaming fixtures must detect stale-slot reuse and premature frees. On real Metal/Vulkan/CPU, measure startup and steady-state peak memory, host/device duplication, conversion staging, allocation success, throughput and transfer overlap for the selected deployment manifest. Stress under the actual memory budget rather than extrapolating from parameter bytes.

**Risk.** Unified-memory mappings do not remove the system-memory budget, and async reuse requires correct fences. **Hypothesis:** the target is achievable for selected quantized GQA models and short contexts after these changes; no measured fit is established by this roadmap.
